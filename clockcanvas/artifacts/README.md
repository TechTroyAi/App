| file | what it is |
|---|---|
| `ClockCanvas-v1.0.0-installable.apk` | release build, versionCode 1, **v2 + v3 signed** with `clockcanvas/.signing/clockcanvas-release.p12`, minSdk 26, targetSdk 35. Includes the media wall (photo/video-only designs with a rotating reel). |
| `ClockCanvas-v1.0.0-installable.apk.sha256` | SHA-256 of the file above (one line, no filename) |
| `ClockCanvas-v1.0.0-content-hashes.txt` | the three byte-stable payloads, for reproducible-build checks |

This build is the UI revision: the RGB/hex colour picker, the media vault (a picked photo is
copied into the app instead of referencing a URI whose grant expires), the icon redrawn as a
vector-style master, and the editor's prose cut back to the lines that prevent a wrong
expectation. The APK is *smaller* than the media-wall build despite adding all of that: the new
launcher icons compress better than the previous artwork.

The certificate has moved twice today (`eb1a34a3…` → `edef1c4e…` → `051398ae…`) for one reason:
the release keystore is git-ignored, and the ephemeral build sandbox that held each key was
recycled between sessions; each new key was minted only with the explicit
`CLOCKCANVAS_ALLOW_NEW_KEY=1` opt-in, and `tools/verify-release-cert.py --record` refreshed
`ClockCanvas-release.cert` each time. Nothing was installed under the earlier identities (they all
predate this release), so no update path is broken — but once anything is out in the wild, restore
`clockcanvas/.signing/` *before* building, and the guard will keep you honest.

The whole-file hash is *not* stable across rebuilds: APK Signature Scheme v2/v3 embeds a
fresh nonce per signing run. The payloads are, and that is what reproducibility can be judged
on — `ClockCanvas-v1.0.0-content-hashes.txt` records them, and a rebuild on another machine
should reproduce all three:

```
a31388ee3563781801045a6443d8b90ce18eb9c4dd0eec043e8de323b53170ff  classes.dex
2574915acedbe490a510f64e6cdbeb08b51ea484e58336caae9355666e2e9101  resources.arsc
4d2a3bc50930a98a5677fd261008852a4efe841d1073c72b4ca641052031b53b  AndroidManifest.xml
```

Install with `adb install -r ClockCanvas-v1.0.0-installable.apk`, or sideload it (offer to
"install unknown apps" for your browser/file manager, since it is not from Play).

**Updates.** An APK only replaces an installed ClockCanvas if it carries the *same signing
certificate* and a *higher versionCode*. The key is not in git (`.gitignore` covers
`.signing/` and `*.p12` like the rest of this repo), so if you rebuild without restoring the
key, the builder refuses to mint a new one; set `CLOCKCANVAS_ALLOW_NEW_KEY=1` only when you
intend a new signing identity, which means users must uninstall first and lose their
`files/clockcanvas/designs` (widget bindings survive, designs do not).

**Verified before committing** (all of this is `tools/build-offline-apk.py`'s last step):

- `apksigner verify --print-certs` → v2 + v3 schemes valid, one signer, DN as above
- dex format 038, size/checksum/SHA-1 self-consistent, **every referenced type resolvable**
  across the bundled classes (Kotlin stdlib included) — the check that catches "compiles but
  crashes with `NoClassDefFoundError`"
- `resources.arsc` and `classes.dex` stored uncompressed, all 4-byte aligned and the mmap'd
  entries page-aligned
- manifest: package, versionCode/Name, min/targetSdk, launcher exported, widget provider +
  wallpaper service present, and no `<activity>` for the Compose screen that this build path
  does not compile
- 5 fonts + 5 OFL licence texts present in `assets/`

`scripts/verify-apk.py` at the repository root can also be pointed at this APK: its sections
1–4 (ZIP layout, signing, dex integrity, manifest) apply and pass. Sections 5–6 are
Blockhold/CleanLead-specific sprite and audio heuristics and report *their* project's assets,
not ours — use `tools/build-offline-apk.py` for the resource cross-check.
